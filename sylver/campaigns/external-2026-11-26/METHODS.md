# Methods

All code is in `code/`. It was written for this work and shares no source
with Cilibrasi's solvers. The two certificate checkers also share no code
with our own solvers or with each other.

## Game conventions

A position is the numerical semigroup S generated by the numbers named
so far. A legal move is a gap a of S. Naming 1 loses at once, so:
- a position whose only gap is 1 is P (terminal), and
- 1 is never a winning move.

A finite position (gcd 1) has Frobenius number F. Its state is the Apéry
set mod M, where M is the smallest generator (M ≤ 16 here). It is stored
as a 15-byte Kunz-coordinate key, always compared exactly.

## fin3: finite solver (`code/solvers/fin3.rs`)

fin3 is an exact solver for finite positions with about 1e9 states,
in under 3 GB of RAM.
- **P-table:** every P-position found is kept in RAM, in 16-byte records,
  and appended to a **P-journal**. The journal is the checkpoint, and it
  is also the certificate input Q.
- **N-positions:** they go only to a lossy cache. An evicted N is
  re-proved by enhanced transposition cutoff (ETC), from a child already
  in the P-table.
- **Values are exact:** a position is recorded P only after all its
  children are N.
- **Rules:**
  - R0: F ≤ 1 ⇒ P.
  - R1 (with ENDER=1): the ender rule, F > 1 and no two gaps a < b with
    a + b = F ⇒ N. This is Hutchings' theorem; see Sicherman,
    *Theory and Practice of Sylver Coinage*, Integers 2 (2002) G2 §1, §3,
    Weak Antisymmetry.
  - No other lemma is used.
- **Validation** (`code/validation/`, 2026-10-18; summary
  `runs=768 agree=766 CONTRA=0 timeout=2`):
  - 383 finite positions × ENDER on/off: 766 agree with our independent
    solver `solve.rs`, 0 contradictions.
  - Cilibrasi's finite ledger witnesses {16,23,36}, {16,17,90},
    {13,16,140}, {11,16,58} and {16,21,156} all come out P.
  - A kill and resume from the journal gives the same verdict.

## P-set certificate and the checkers

**Claim checked.** Every key X in Q is P. The checker verifies, for each
X in Q:
1. X is the Kunz vector of a numerical semigroup containing the root
   (the Kunz inequalities, and containment of every root generator).
2. For every gap a ≥ 2 of X, the child Y = X + a has F(Y) > 1. If not,
   X has a terminal P child, and the check **FAILs**.
3. Y has some reply y ≥ 2 with Y + y in Q, or with Y + y terminal.
   With ENDER=1, Y may instead pass as an ender. Each such use is counted
   and the key logged.

Finally, the root itself must be in Q, and gcd(root) must be 1.

**Soundness.** Use induction on the number of gaps. Every child of X is
N, and the move 1 loses, so X is P. N-positions are never stored; they
are re-proved on the fly from Q. Memory is therefore bounded by |Q|, not
by the size of the search.

| Checker | Language | Position representation | Q lookup |
|---|---|---|---|
| `checkq.c` (v3) | C | gap bitmap; a move is a bitset closure | open-addressing hash table (2× keys) |
| `checkq_lm.c` | C | same check logic as checkq | static sorted array plus bucket index (low memory). Keys are visited in journal order, so its counters equal checkq's |
| `checkq2.rs` | Rust | Apéry vector; a move is w'_r = min_j (w_{(r−ja) mod M} + ja) | static table of u128 keys sorted by (mix, key), with a CSR bucket index |

checkq_lm is a memory variant of checkq, **not** an independent method.
On every two-checker row the pair is {checkq or checkq_lm, checkq2}: one
C gap-bitmap implementation and one Rust Apéry-vector implementation.

**Tests** (`code/tests/`; outputs in `certificates/tests/`): 24 cases per
checker, all as expected for checkq, checkq_lm and checkq2.
- **OK:** five known-P journals, a terminal P, and duplicated records.
- **FAIL:**
  - a false P key added;
  - the root dropped;
  - 10% of Q dropped;
  - a Kunz-violating key;
  - a semigroup that does not contain the root;
  - a child that reaches the terminal;
  - a bit-flipped record;
  - N roots {5,16} and {11,16}, also with the root forged in.
- **ERROR:** header/root mismatch, a gcd > 1 root, a wrong root, a
  missing file.
- **Resume:** a checkpoint/resume run gives the same counts as a fresh
  run.

checkq_lm's test output is identical to checkq's. On the five OK
journals, checkq2's children counts are identical to checkq's.

**Reproduction (2026-11-26).** All three checkers were rebuilt from the
sources in `code/checkers/` with:
```
gcc -O2 -o checkq checkq.c
gcc -O2 -o checkq_lm checkq_lm.c
rustc -O -o checkq2 checkq2.rs
```
The three suites were re-run on the rebuilt binaries. All three gave
24/24, and each output is **byte-identical**, including every probe
count, to the output recorded when that checker was certified:
- checkq: `tests_orig.out`.
- checkq_lm: `tests_lm.out`.
- checkq2: `tests2c.out`, the final killer-table version. `tests2.out`
  and `tests2b.out` are from earlier reply orders.

The outputs are in `certificates/tests/rebuild_20261126_*.out`. The
rebuilt binaries do not hash-match the ones used for the certificate
runs (`BINARIES.tsv`), because the original build flags were not
recorded. Only behaviour is compared.

**Running a certificate** (paths as on our box; edit as needed):
```
ENDER=1 ENDERLOG=enders_<case>.bin CKPT=ck_<case> CKSTEP=1000000 ./checkq_lm J.bin 16 38 72 84 139
ENDER=1 ENDERLOG=enders_<case>.bin CKPT=ck_<case> CKSTEP=1000000 THREADS=1 ./checkq2 J.bin 16 38 72 84 139
```
Wrappers: `code/scripts/run_cert.sh`, `run_cert_lm.sh` and
`run_cert2.sh`. RAM use was:
- checkq: about 2 × |Q| × 16 B. For 69M keys that was 5.2 GB.
- checkq_lm: about 1.3 GB on 69M keys.
- checkq2: 571 MB on 32M keys.

## Use of the ender theorem, and removing it

With ENDER=1, the checkers accept an ender child Y as N without
exhibiting a reply. These are rows marked "conditional on the ender
theorem". To remove the dependency (`code/scripts/ender0/`):
1. `gens.py`: list each distinct logged ender child by its minimal
   generators.
2. fin3 with ENDER=0 solves each one, using only R0 and no theorem. All
   must be N. The results are in
   `certificates/reply38/ender_free/ender_children_*.tsv`.
3. `merge.py` / `merge_lm.py`: build Q' = Q ∪ (those children's
   P-journals, re-keyed mod 16), with keys already in Q dropped.
   merge_lm.py reproduced merge.py's 68+257 Q' byte for byte.
4. Re-check Q' with both checkers with ENDER=0. Both report `enders=0`.

This was done for 68+257 and 100+245 only.

## g=2 and gcd-4 lanes (reply-40 and odd-answer sweeps)

- **even3** (`code/solvers/even3.rs`) solves g = 2 positions
  T = 2·S:
  - Moves into odd numbers give finite positions; by the Quiet End
    Theorem only the gaps need search.
  - Even moves recurse.
  - Long positions are decided by **pattern2/pattern3**, an exact
    odd-move cycle detector. It declares a cycle only on full window
    equality.
  - A failed pattern call (memory) is counted in `pfail` and treated as
    UNKNOWN, never as a value.
- **even3 validation:**
  - 210 literature positions: 147 agree, 0 contradictions, 63 time out.
  - Anchors: {12,14,16} P, {10,16,24} P.
  - Node count on {16,18} identical to even2.
- **g4lane** (`code/scripts/g4lane.py`): for each reply r and candidate
  a, it runs fin3 (odd a, finite) or even3 (even a) with a per-try limit
  (TRY_TO = 10,800 s).
  - Every attempt is appended to `tries.tsv`.
  - TIMEOUT rows stay unknown.
  - `ERR(rc=…)` rows mean the solver crashed and gave no value.
  - The full log is `certificates/lanes/g4lane_tries.tsv`.

## Independent brute force (vchk) and the second-method items

- **vchk.c** (`code/solvers/vchk.c`, C bitset brute force + QET, with
  optional P-lemmas, never the position under test).
  - Finite engine: 40/40 against a Python brute force (`brute.py`).
  - Blok's 6-16 Tables: 372/372 finite rows agree, and each listed
    winning move was checked to give a P child.
  - Blok's even rows: 0 contradictions (`verify/REPORT.md`).
- **solve.rs:** an independent exact finite solver, used as the second
  engine for the Blok 251→25 check and the ledger replays.
